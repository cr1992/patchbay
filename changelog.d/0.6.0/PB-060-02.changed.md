- **Breaking:** `package:patchbay/patchbay.dart` 与 `package:patchbay_flutter/patchbay_flutter.dart` 收窄为按角色
  分层的封闭清单，并新增三个显式入口。默认 core 入口保留 98 个 consumer 符号（命令注册与 descriptor、参数与
  响应 schema、gate、catalog/snapshot provider、job、artifact/blob/log、navigation 与 UI 声明），默认 Flutter
  入口不再整库 re-export core，只在该清单上追加 `PatchbayKey`、`PatchbayRoot`、`PatchbayRootController` 与
  `PatchbayUiRegistry`（共 102）。新增 `package:patchbay/patchbay_host.dart`（136：默认清单的严格超集，再加
  `PatchbayServiceHost`、audit、invocation/cancellation 与 validation lifecycle）、
  `package:patchbay/patchbay_protocol.dart`（141：生成 wire 类型、catalog capability/digest、CLI syntax、
  permission companion、client 请求与 canonical descriptor）与
  `package:patchbay_flutter/patchbay_flutter_host.dart`（195：core host 清单加全部 Flutter service host、
  bridge 与 policy）。wire、错误码、稳定 JSON、资源上限与运行时行为都没有变化，本项只改 Dart 源码可见性。
  迁移：旧 import 会编译失败，按报错点名的符号在[使用指南的迁移表](docs/guide.md#05x--060-source-迁移表)里
  查对应入口。每个入口都是**自足**的——导出符号的公共签名里出现的 Patchbay 类型一定由同一入口导出——所以
  照表改完不会再遇到 `undefined_class`；代价是默认面里保留了少数 `*Wire` 与 CLI syntax 类型
  （`PatchbayLogQuery` 收 `PatchbayLogLevelWire`、`PatchbayRedactedLogRecord` 公开 `PatchbayLogRecordWire`），
  几份清单也因此有意重叠，同时 import 两个入口不会冲突。不提供 `legacy.dart`，也不保留兼容的整库
  re-export。`patchbay_cli`、`patchbay_client` 与 `patchbay_transport` 的公共符号集合不变。
