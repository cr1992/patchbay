- 修复 snapshot single-flight 在 provider 采样永不返回时会把整个 App 的 snapshot 面拖死的问题：一次挂死的
  采样以前会被永久登记为「进行中」，此后 direct 与 VM Service 两侧所有 snapshot 读——完整读、路径选择、
  `fromRevision` diff 与带 `timeoutMs` 的 wait——都会并入这条死采样并永不答复，连 wait 自己声明的
  `timeoutMs` 预算也被吞掉，provider source 也不再被调用第二次。现在共享只覆盖真正进行中的采样：加入
  他人采样的调用者以自己的剩余预算为上限等待，预算耗尽即按既有 `snapshotWaitTimeout` 答复，并把这条
  采样从「进行中」摘除，于是下一次调用重新采样。发起采样的调用者行为不变，仍等自己的 source 读完、再由
  预算裁决那份答复是否还算数；预算未耗尽的并发调用者也仍然共享同一次采样。相应地，
  `snapshotWaitTimeout` 的 `details` 在一次轮询都没有完成时不再给出 `observed`（此时 `polls` 为 `0`），
  避免把「App 始终没有答复」写成「字段不存在」；既有能完成轮询的答复逐键不变。
