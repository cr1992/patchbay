title: 候选分支的接入方可验性：包间互引是 hosted 形态，直接 git 依赖会 version solving 失败
target: 0.6.0
status: 已验证
---

## 动机

0.5.0 两个接入方验收实证：接入方想通过 git 依赖直接 pin 候选分支做验收，version solving 失败——四个包的 `pubspec.yaml` 包间互引全部声明成 hosted 约束（例如 `patchbay_cli` 依赖 hosted `patchbay_transport`），只把其中一个包换成 git 源时 pub 无法调和 hosted 与 git 两种来源，唯一出路是四个包一起写 `dependency_overrides`，且没有文档指路

## 备注

发布态继续使用 hosted 约束，候选期不临时发布 prerelease；`candidate-consumer` 从 workspace 生成四包同仓同完整 SHA 的 `pubspec_overrides.yaml` 并校验 consumer lock 的 URL、ref、resolved-ref 与 path，最小 Flutter consumer 已真实 `pub get` 通过，接入步骤见 [候选接入说明](../candidate-validation.md)
