## 动机

0.5.0 的 Linux procfs 快路径只用 `$procRoot/$pid` 是否存在判断 PID namespace，数字 PID 碰撞时会同时误报 liveness 与启动签名；拒信后若回退 GNU `ps` 仍会读取同一外来 procfs，并非独立证据；三个 scheme 的 writer/reader 又分别维护校验，导致 POSIX/Windows 的语义非法日期被当成可比身份、procfs 的带符号 ticks 能写却不能读。修复按 [会话启动身份签名 Proposal](../proposals/0.5.0/session-identity-signature.md) 的 0.5.1 增补裁决收口：procfs 只有在 `self/status` 的 `NSpid` 单段且等于当前 Dart PID 时才可信，无法证明时 liveness 回退 `kill`、启动签名返回 `null`；签名统一经同一 codec 编解码，日期载荷校验 C locale 枚举、字段范围与日历一致性，畸形值只降级 `identityUnverified`，不判死。新增回归在旧实现上按预期覆盖 namespace 数字碰撞、外来 procfs 下禁用 `ps`、非法日期与 writer/reader ticks 漂移四类红；修复后 `patchbay_cli` 全量 738 绿、1 个 Linux-only 如实跳过，`dart analyze --fatal-infos`、planning、API surface、structure hard rules 与 `git diff --check` 全过；本条不改命令面、wire 或公共 API，真 Linux procfs 路径交 GitLab CI 复验，仓主裁决先积攒于 0.5.1、不立即发布
