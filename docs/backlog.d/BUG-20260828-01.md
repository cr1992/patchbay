---
id: BUG-20260828-01
title: 启动身份签名只校验 scheme 不校验 payload，畸形记录被判成 PID 复用并删除
status: 已验证
---

## 动机

PB-050-31 把签名改成 `<scheme>:<payload>` 并引入三态比较，但 `compareStartTimeSignatures` 只比较 scheme 标签，随后无条件相信标签后面的内容：scheme 标签说的是「这个字符串自称是哪种格式」，不是「它确实是那种格式」。于是被截断或损坏的记录（如 `v2-linux:garbage`、`v2-linux:<boot_id>` 少了 tick 段、`v2-posix:` 空载荷、`v2-win:` 带本地偏移）与一条完好的探针落进「同 scheme、payload 不等」分支得 `different`，`_checkProcessIdentity` 据此判 PID 复用，把一个 App 仍在运行的会话记录删掉——正是 PB-050-31 自己确立的红线（无法验证绝不判死）要杜绝的结果，与 BUG-20260827-01 同属「探测/解析侧的不确定被当成确定结论」。修复：三个 scheme 各自补上从写入侧代码反推的 payload 契约（`v2-linux` 为 UUID 形态 boot_id 加十进制 tick 数，不要求为正——PID 1 合法地从 0 起算；`v2-posix` 只断言写入侧 trim/collapse 已保证的性质，即非空、无 ASCII 控制字符、无首尾空格与连续空格，不断言日期形状，因为 BSD 与 GNU `ps` 的渲染本就不同；`v2-win` 为 `"o"` 往返格式的 UTC 瞬时，必须以 `Z` 结尾，本地偏移即 PB-050-31 缺陷的 Windows 形态），任一侧 payload 不合契约一律 `unverifiable` 降级为 `identityUnverified`；两侧合法且同 scheme 下不等仍照旧判死，PID 复用守卫不弱化。过严与过松不对称——过严只会少一次 `different` 让陈旧记录多留一会儿，过松会删掉活会话的记录——契约据此取「写入侧能写出的值必须全部合法」的下限。**已跑证据**：`packages/patchbay_cli` 全量 731 用例绿（基线 724 + 新增 7），`dart analyze --fatal-infos` 零告警；证伪核实为把 lib 改动 stash 后重跑，新增 7 条中恰好 4 条（两条畸形矩阵 + 两条 resolver 端 `inventory()`/`select()` 保留记录）红，其余 3 条（合法对仍判 same/different、契约不过严、真实 procfs 签名能被自己读回）在修复前后同绿，说明它们钉的是不回归而非本缺陷；未跑真机 example 预检——本条不改命令面、wire 与公共 API，`api_surface` golden 零变化
