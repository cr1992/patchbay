## 动机

`packages/patchbay/tool/command_codegen.dart` 为任何声明了 commands 的合约无条件产出 decode-result 类型（第 526 行 `final PatchbayRejection? rejection;` 与第 588/600/608/623/632 行的构造），而同一文件第 174–178 行把 `descriptorImport` 限成封闭二选一 `package:patchbay/patchbay.dart` 与 `package:patchbay_flutter/patchbay_flutter.dart`——PB-060-02 恰好把 `PatchbayRejection` 移出了这两个默认面（现只在 `patchbay_host.dart` 与 `patchbay_flutter_host.dart`），于是两个合法取值产出的代码都编不过，且生成文件带 DO-NOT-MODIFY 标记、手改会被下次生成覆盖——接入方通常还把 `command_codegen --check` 作为 commit 级漂移闸，于是不改则编译红、手改则漂移闸红，consumer 侧没有合法状态；用仓内 `contracts/example_commands.json` 即可复现：`dart run packages/patchbay/tool/command_codegen.dart --contract packages/patchbay/contracts/example_commands.json --output <tmp>/lib/gen.g.dart --write` 产出 6 处 `PatchbayRejection`，拿 path 依赖 analyze 得 8 个 `undefined_class` / `undefined_function` / `invalid_constant`。仓内门禁结构上抓不到：`contracts/example_commands.g.dart` 只是 4 行 sha256 快照而非真 Dart，`test/command_codegen_test.dart` 只做字符串断言，生成的 Dart 从未被 analyze 或编译。修法是裁决点——`PatchbayRejection` 属 consumer 面（生成的 decode-result 是 consumer 侧代码，回补默认面要动 DG-060-02 已冻结的入口清单）还是扩 `descriptorImport` 封闭集接纳 host 入口，本条不预设。
