status: 实现中
---

## 动机

`packages/patchbay/tool/command_codegen.dart` 为任何声明了 commands 的合约无条件产出 decode-result 类型（第 526 行 `final PatchbayRejection? rejection;` 与第 588/600/608/623/632 行的构造），而同一文件第 174–178 行把 `descriptorImport` 限成封闭二选一 `package:patchbay/patchbay.dart` 与 `package:patchbay_flutter/patchbay_flutter.dart`——PB-060-02 恰好把 `PatchbayRejection` 移出了这两个默认面（现只在 `patchbay_host.dart` 与 `patchbay_flutter_host.dart`），于是两个合法取值产出的代码都编不过，且生成文件带 DO-NOT-MODIFY 标记、手改会被下次生成覆盖——接入方通常还把 `command_codegen --check` 作为 commit 级漂移闸，于是不改则编译红、手改则漂移闸红，consumer 侧没有合法状态；用仓内 `contracts/example_commands.json` 即可复现：`dart run packages/patchbay/tool/command_codegen.dart --contract packages/patchbay/contracts/example_commands.json --output <tmp>/lib/gen.g.dart --write` 产出 6 处 `PatchbayRejection`，拿 path 依赖 analyze 得 8 个 `undefined_class` / `undefined_function` / `invalid_constant`。仓内门禁结构上抓不到：`contracts/example_commands.g.dart` 只是 4 行 sha256 快照而非真 Dart，`test/command_codegen_test.dart` 只做字符串断言，生成的 Dart 从未被 analyze 或编译。已修：生成的命令代码本就是 host 侧代码（它构造 `PatchbayRejection`，调用它的派发器构造 `PatchbayInvocation`，两者在 PB-060-02 的分层里都是 host-only），因此错的不是分层而是 `descriptorImport` 的封闭集没跟着改——封闭集改为只接受两个 `_host` 入口，两个旧 consumer 面取值逐值拒绝并点名唯一替代值，DG-060-02 冻结的入口清单不动；同时补 `test/generated_command_surface_test.dart`，对每个合法取值生成真 Dart 并与 `tool/api_surface.json` 的冻结清单对账，缺陷态下该测试对两个取值都报 `[PatchbayRejection]` 缺失。
