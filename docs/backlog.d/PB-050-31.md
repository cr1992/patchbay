---
id: PB-050-31
title: 会话启动身份签名改用时区无关的持久化格式
target: 0.5.0
status: 已验证
---

## 动机

`PlatformProcessUtils.processStartTimeSignature` 在 POSIX 上取 `ps -o lstart=` 的输出，那是**按本地时区格式化**的字符串；同一 PID、同一时刻在不同 TZ 下得到不同结果（容器实测：`TZ=UTC` → `Thu Aug 27 06:51:14 2026`、`TZ=Asia/Shanghai` → `Thu Aug 27 14:51:14 2026`、`TZ=America/New_York` → `Thu Aug 27 02:51:14 2026`）。记录写入与读取跨了 TZ——不同 shell、cron、CI job、`/etc/localtime` 不同的容器，或仅仅跨过一次 DST 切换——两个非 null 签名就会不等，`_checkProcessIdentity` 据此判 PID 复用，把一个活着的会话判死并删记录。Windows 的 `.ToString("o")` 同形（含本地偏移）。与 BUG-20260827-01 同属 fail-closed 类：探测机制自身的不稳定被当成「这是另一个进程」的确定结论

## 备注

**升级记录**：登记时按「稳定 JSON 变更需先过 Proposal」列为 `待排期`；仓主外部评审推翻该理由并升为 0.5.0 发布阻断——`processStartTime` 是 PB-050-18 在本版新增的字段，0.5.0 未发布，该格式从未成为对外契约，改它的兼容成本为零，不存在需要 Proposal 冻结的既有语义；唯一需要善待的是开发期间已写出的记录（接入方候选验收、仓内联调），处理方式沿用 BUG-20260827-01 已确立的三态纪律，不新增决策。**修复**：签名改为 `<scheme>:<payload>`，三种来源三个 scheme——`v2-linux` 取 `/proc/<pid>/stat` 第 22 字段（`starttime`，自开机起的内核 tick 数）配 `/proc/sys/kernel/random/boot_id`（内核原值、零格式化、跨重启唯一，且不派生子进程；缺 boot_id 时不降级发一个只在单次开机内唯一的弱签名，而是回退 `ps`），`v2-posix` 仍走 `ps -o lstart=` 但把 `TZ=UTC` 与 `LC_ALL=C` 一起钉进子进程环境，`v2-win` 走 PowerShell `.ToUniversalTime().ToString("o")`；比较改为 `compareStartTimeSignatures` 三态：scheme 未知或两侧 scheme 不同一律 `unverifiable`（降级 `identityUnverified`，绝不判死，即便两个字符串恰好相等也不认作已核实），同 scheme 下不等仍判死，PB-050-18 的 PID 复用守卫语义不变；`/proc/<pid>/stat` 从**最后一个** `)` 向右切，避免 `comm` 含空格/括号时字段整体错位。**`LC_ALL` 是实测追加的第二条独立不稳定源**，登记时未记入：把 `TZ` 钉成 UTC 之后，同一时刻 `ps -o lstart=` 在 `LC_ALL=C` / `de_DE.UTF-8` / `fr_FR.UTF-8` 下仍分别渲染成 `Fri Aug 28 …` / `Fr. 28 Aug. …` / `ven. 28 août …`，只钉时区会留下第二条同型缺陷。**已跑证据**：`packages/patchbay_cli` 全量 724 用例在 macOS(arm64, Dart 3.12.2) 绿；四个会话相关套件在 Debian trixie / arm64 / Dart 3.13.2 容器内以 `TZ=Asia/Taipei` 跑绿；真实往返（同一个从未退出的 `sleep` 进程，记录在一个 TZ 写、在另一个 TZ 读，走真实 `PatchbaySessionRecord` + `PatchbaySessionResolver.inventory()`）——`TZ=UTC` 写、`Asia/Taipei` / `America/New_York` / `Australia/Lord_Howe` 三个 TZ 读，均得 `status=live`、`identityUnverified=false`、记录留存，同一次运行里以修复前的裸 `ps` 探针做对照组，三个 TZ 全部得出 `STALE → store.remove()`，即缺陷本身在同一环境下确实复现；开发期旧格式记录（无 scheme 前缀）跨 TZ 读得 `status=live` + `identityUnverified=true`、记录留存；`dart:stable` 镜像无 `procps`，`v2-posix` 回退如实返回 `null` 而 `v2-linux` 照常作答，四个 TZ 下签名逐字节相同。**未跑**：`tool/example_precheck.sh`（需连着的 Android/iOS 设备）——本条不新增命令面也不改 wire，签名函数不在公共 API 面，`api_surface` golden 零变化，端到端证据由上述 Linux 往返承担
