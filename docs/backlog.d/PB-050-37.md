## 动机

invocation 现拥有 execution slot、active-owner 上限、owner token、cancellation control slot、settled tombstone、replay ledger、transport processing slot、四类终止源(deadline/disconnect/explicit cancel/dispose)与 audit drain 顺序,完整生命周期横跨 host invoker、direct transport、audit、CLI 与 consumer callback;规模与分布已核实:`packages/patchbay/lib/src/host/invocation_coordinator.dart`(417 行)持有 `activeOwnerCapacity`/`settledTombstoneCapacity` 均为 256(29-30 行)、owner map 与 tombstone 队列(36-39 行)、owner token 校验(65-67 行)、容量守卫(90-97 行)、cancellation controller 与 deadline timer(111-136 行),四类终止源即 `invocation_cancellation.dart:7-10` 的 `PatchbayInvocationCancellationReason`(`callerDeadlineExceeded`/`callerDisconnected`/`explicitRequest`/`hostDisposed`);`packages/patchbay/lib/src/host/host_invoker.dart`(699 行)另持 requestId replay ledger(429-432,499,549,554 行)与 audit ledger/`drainAudit`/`_recordAudit`(72-90,605-622 行)。普通单测难以覆盖状态组合爆炸,方向:把状态转换/容量占用/终态仲裁整理成可执行状态模型做属性测试,不变式至少:每 owner 至多一个终态;每 slot 恰好释放一次;未确认取消绝不释放容量;replay 绝不产生第二次副作用;dispose 后不再产生新 owner

## 备注

纯测试工程,不改运行时语义;落地前无需 Proposal,但状态模型若倒逼语义修正则该修正另走裁决
