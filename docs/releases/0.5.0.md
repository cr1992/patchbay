# Patchbay 0.5.0 版本计划

> 状态：规划中
>
> 范围真源：本文定义 0.5.0 的优先级、依赖和退出条件；[backlog](../backlog.md)
> 保存条目标题、动机、目标版本与实施状态。
>
> 发布方式：从稳定 `main` 创建 `dev/0.5.0`；范围、Proposal 与实现 MR 均以该分支为目标。
> 本文状态推进到 `RC` 即冻结范围，通过门禁后再由一个发布 MR 合回 `main`。

## 版本定位

0.5.0 是一次 host 可靠性、高频调用成本与 CLI 自动化契约治理版本。它不增加接入方业务命令；计划新增的
identifier action 是 protocol-owned UI 命令，不扩张 consumer catalog namespace。本版同时收紧 provider、
目录、审计和 invocation 四条边界，修复 REPL 流式终止答复，并降低 snapshot wait、带参数 invoke 与
semantics probe 的重复工作。

本版把两类工作明确分开：

1. 已有契约无法兜住的正确性缺口先修，特别是 snapshot source 的非 JSON、循环引用与活对象逃逸；
2. 会新增资源上限、缓存失效、异步投递或取消语义的工作先完成 Proposal 裁决，不以“性能优化”名义
   静默改变失败形态。

0.5.0 不以“所有路径都加缓存”为完成。每项优化必须先有基线，证明减少的是实际热点，并同时证明
valid payload 的稳定 JSON、整份 catalog fail-closed、semantics generation 和超时后容量保护没有漂移。

## 范围分级

### P0：发布阻断

| 编号 | 关键验收 |
|---|---|
| PB-050-01 | source 抛错、非 JSON 值、非字符串 key、活动路径循环和过深结构都在 host 边界变成既有 `providerProtocolViolation`；共享但无环的子树只在展开节点/增量 canonical 字节硬预算内合法，指数扇出必须在产生完整副本/String 前中止；有效 snapshot 的字段顺序、revision/diff 与 VM/direct 输出不变，返回体不再引用 consumer 活对象 |
| PB-050-05 | audit sink 单消费者按 host 记账顺序调用，前一项 Future settle 前不启动后一项；pending 数量有界，overflow 与 sink failure 均通过既有 error observer 可观测，且永不改写已经发生的命令结果 |
| PB-050-08 | `--json repl` 的正常结果与 transport / protocol / session 终止错误都各占一个 LF 结尾的 compact JSON object；终止继续使用既有 error envelope 与退出码，stderr 仍只做人读诊断；按行 parser 能读取最后一条后发现 EOF，不再收到 one-shot pretty JSON |

### P1：本版目标

| 编号 | 关键验收 |
|---|---|
| PB-050-03 | 带参数 registry/external 调用的 catalog 构造、descriptor JSON、canonical 与 digest 次数有基准和计数断言；优化后非法名、重名、动态目录漂移与 sensitive stdin 门仍逐项 fail-closed，不允许用 registry 命中绕过整份目录有效性 |
| PB-050-04 | 分别量出 `ensureOwner` 主动请帧、`endOfFrame` 等待、`ui.wait` 再等待与树扫描的成本，交付可复现 benchmark 与决策建议；本条不改变请帧、等待、缓存、generation 或稳定响应行为 |
| PB-050-02 | retention 同时受 revision 数和 canonical UTF-8 总字节约束；单份超限不污染 latest，双淘汰后 diff 可用性与 `snapshotRevisionUnavailable` 可预测；并发读只共享 provider sampling，不合并各自 deadline/selection；可选 consumer revision 不破坏旧 source typedef |
| PB-050-06 | deadline、调用方放弃等待、host dispose 与显式 cancel 的事实来源可区分；只有 handler settle 或 cooperative cancellation 被确认后才能释放执行容量；registry/external 与 VM/direct 受同一 host admission 预算约束，legacy handler 有明确降级且 job cancellation 语义不变 |
| PB-050-07 | 以 PB-050-04 数据裁决 owner 已可用时的请帧策略、`ui.wait` cadence 与 identifier cache；任何优化都须保持 owner/tree 失效、node identity 与 generation 二次复核，并明确 elapsed/frameRevision/timeout 的兼容变化 |
| PB-050-09 | `sessionDirectoryEmpty` 同时指向 `patchbay launch -- <consumer command>` 与显式 `--ws-uri`；raw `ui.capture` / `blob.read` 的帮助就地指向已有的 `capture ... --output` / `blob get ... --output` 自动分块落盘入口；`text.set` 的人读成功摘要与 help 明示不调用 formatter/onChanged，`text.enter` 明示会调用；help 解释 `id` / `identifier` 是 target 与 Semantics 两个身份域、`limit` / `length` 是请求上限与实际响应长度；REPL 内 `describe <service-command>` 有回归测试与示例，且不新增别名或第二套 schema 命令，JSON 输出逐字节不变 |
| PB-050-10 | 新 identifier action 在一次 App 受理中完成唯一解析、内部 generation pin、policy/gate 与门后二次复核；省略 caller generation 不省内部围栏，换代/歧义不自动重试；只覆盖既有七项公开 action allowlist，unknown key fail-closed；dispatched/failed 保持各自现有字段形状，旧 tap/nodeId action JSON 不变 |

### P2：本版不排期

不为填满小版本追加 UI 命令或平台能力。P0/P1 完成后直接进入 RC。

## Proposal 闸门

- PB-050-01 的 [provider 边界 Proposal](../proposals/0.5.0/snapshot-provider-boundary.md) 先冻结失败投影和
  有效 JSON 的字节兼容；接受前只允许增加能复现当前崩溃的失败测试。
- DG-050-01 至 DG-050-06 必须分别裁决并将 Proposal 改为“已接受”，对应实现才能合入。
- Proposal 可以独立评审；实现 MR 不得同时夹带尚未接受的另一个 Proposal。需要共同底座时先合底座，
  修改 `host_invoker.dart` 的 PB-050-03、PB-050-05、PB-050-06 串行推进。

## 明确不进入 0.5.0

- 不把 snapshot canonical String 直接换成 digest：摘要仍需遍历全部字节，且当前 canonical 还承担
  精确去重；只有基准证明整体更优时才能作为 PB-050-02 的实现细节讨论。
- 不把 `revision.body` 直接替换成现有响应 body：canonical key 排序会改变有效 JSON 输出；PB-050-01
  必须用保持插入顺序的冻结副本单独解决活对象问题。
- 不把 source revision 作为 `PatchbaySnapshotSource` 的新参数或返回字段强塞进既有 typedef；旧接入方
  无修改继续工作是 PB-050-02 的验收条件。
- PB-050-04 只做量测；不用“透明降载”名义改变主动请帧或 `ui.wait` 时机。PB-050-07 接受后若使用索引，
  不用 identifier entry 快照替代 node 引用，也继续执行 tree revision、identity 与 generation 复核。
- 不在 direct timeout 时无条件释放 slot；缺少 cooperative cancellation 证明时继续保留现有容量保护。
- 不把 job ledger 纳入“无界事件”修复；现有每个 job 为 running 加一个终态，保留/淘汰契约不在本版改写。
- 不新增 `--jsonl`：REPL、`logs tail` 与 launcher 已承诺按行输出；PB-050-08 修的是终止错误逃到 one-shot
  pretty formatter 的契约破口。
- 不再新增 `ui capture` / `--out` 别名：CLI 已有 `capture root|target --output` 与 `blob get --output`，并负责
  分块、base64 解码、长度与 SHA-256 校验；PB-050-09 修复从 raw service 到这条安全路径的发现链，避免
  维持两套同义命令。
- 不在 PB-050-08 自动重连。REPL reconnect 复用 PB-040-30，须先裁决固定 session、App/device identity、
  runtime replacement 与重试预算，不能因“恢复体验”静默换 peer。
- PB-050-11 的日志 event wire/filter 不进入本版；它会改变公共 log source/query 契约，须独立 Proposal。
  接入方 log source 的即时归一化留在接入方仓，不等待核心契约。
- PB-040-24、PB-040-28、PB-040-30 至 PB-040-37 继续留在 backlog，不借本次 host 治理扩张产品能力。

## 依赖与实施顺序

1. **M0：版本基线**——开建 `dev/0.5.0`，冻结 0.4.1 public surface、snapshot/catalog/audit golden 与 REPL
   正常/终止输出语料，为三条热点增加可重复计数器或 benchmark harness；
2. **M1：正确性边界**——PB-050-08 先用真实 LineSplitter 复现 transport 终止落入 pretty formatter，再以
   既有 error envelope 修复单行终态；并行接受 PB-050-01 Proposal，以失败测试复现 source throw、
   unsupported、cycle、depth、共享 DAG 指数扇出与返回后 mutation，随后实现带展开节点/增量字节硬闸的
   JSON-safe 冻结读视图；
3. **M2：catalog 热路径**——裁决 DG-050-02；先保持全目录验证语义建立失效信号，再优化 policy 获取，
   不从 registry 快路径直接跳过目录有效性；
4. **M3：audit 投递（P0）**——裁决 DG-050-03，先以单消费者建立顺序，再加有界队列、overflow 报告与
   drain；不得等待独立的 semantics/snapshot P1 工作完成；
5. **M4：invocation 生命周期**——裁决 DG-050-04，先加兼容的 cooperative context，再统一 host admission；
   direct 与 VM Service 共享语义后才允许调整 timeout 后的容量回收；
6. **P1 独立轨**——PB-050-09 的 hint/help/测试不改 wire 或运行语义，可独立推进；DG-050-06 接受后，
   PB-050-10 复用现有 tap 双解析原语实现通用 identifier action，不等待 PB-050-04 量测；M1 完成后，
   PB-050-02 可独立推进 snapshot 双预算/single-flight；PB-050-04 只落 semantics instrumentation/benchmark，
   DG-050-05 接受后再实现 PB-050-07 调度或索引。PB-050-10 与 PB-050-07 都修改 semantics bridge，前者先
   合入或后者显式 rebase，不能并行拼两套 resolve；独立轨不得阻塞 M2 → M3 的 P0 收口；
7. **RC**——冻结范围，只接发布阻断修复，跑完兼容、失败注入、压力、debug/profile example 与发布门禁。

M2、M3、M4 都会修改 host invocation 热点，必须按上述顺序串行。PB-050-04/07 与 PB-050-02 分别位于
Flutter semantics 和 host snapshot，可在 M1 后与 invocation 热点链并行；优先级只允许并行，不能让 P1
成为 P0 audit 的前置。单个 MR 可以覆盖一个 PB 的多个文件，但必须给出独立回退点。

## 验证与退出条件

- 四包 format、analyze `--fatal-infos`、test、codegen/check 与
  `release_prep --version 0.5.0 --check` 全绿；
- `dart run tool/check_planning.dart` 保证 0.5.0 范围、Proposal 与 design-gate 无漂移；
- snapshot 失败注入至少覆盖 source throw、`DateTime`/自定义对象、非字符串 key、直接/间接 cycle、
  深度边界、共享无环子树在展开节点/增量 canonical 字节边界内外、超长 scalar、单份与总字节边界、
  淘汰和并发 wait；超限必须在完整展开产物分配前中止，任何异常都不得越过 host 边界；
- snapshot 安全天花板满足 `maxExpandedOccurrences >= maxCanonicalBytes ~/ 2`；1..4 MiB 的合法 payload
  由运行/字节预算分类，不能因 occurrence backstop 提前变成 `providerProtocolViolation`；
- 复刻 0.4.1 reader 读取新的 valid snapshot/catalog/invocation surface，稳定 JSON、`schemaVersion: 1`、
  `revisionSource: hostObserved` 的 legacy 路径与 catalog digest `covers: [commands]` 不变；
- catalog 的正常、非法 command name、重名、动态 UI target、retry policy、response schema、execution
  contract 与 sensitive stdin 矩阵在优化前后逐字节对账；
- audit 压力测试使用可控慢 sink，证明严格单消费者、pending 上限、确定 overflow 统计、sink/error observer
  抛错隔离和 dispose 终态；日志与 error details 不含参数原值；
- REPL 失败注入覆盖 transport、protocol、session identity 与普通 command rejection：前三类各输出一条
  compact terminal error 后按既有非零码退出，普通 rejection 继续留在 session；测试以逐行 `jsonDecode`
  读取完整 stdout，禁止增量 document decoder，并证明本版没有隐式重连；
- CLI 诊断 golden 覆盖空 session directory 的中性恢复指引、raw capture/blob 到自动落盘命令的交叉提示、
  `text.set` / `text.enter` callback 差异、target `id` / Semantics `identifier` 与 request `limit` / response
  `length` 的事实域说明，以及 REPL 内 `describe blob.read` 返回 live descriptor；`--json` 输出保持逐字节
  不变，不得写入接入方私有命令、目录或 console 名称；
- invocation 压力/失败注入覆盖 registry 与 external、VM Service 与 direct、legacy 与 cooperative handler、
  deadline 竞速、迟到 settle、取消拒绝/确认、满容量和 host dispose；不把“调用方不等了”写成“执行已取消”；
- semantics benchmark 在固定树规模下分别记录帧数、owner 获取耗时、扫描节点数和总 probe 延迟；
  PB-050-04 的量测 MR 不改变现有答复。PB-050-07 实现后，空闲 App 不被持续按显示帧率驱动，且
  owner/tree 变更、elapsed/frameRevision/timeout 与 generation stale 按已接受 Proposal 的兼容矩阵全绿；
- identifier action 覆盖七项既有公开 action、显式/省略 caller generation、首次解析前/后换代、歧义、
  policy/gate 漂移与 sensitive setText；新 CLI 对老 host 不降级成两步调用，旧 tap/nodeId action 的 valid/
  rejection JSON 逐字节不变；新 command unknown key 在 policy 前拒绝，dispatched/failed 的 revision、length、
  redaction 与 failureType presence/absence 分别用 golden 冻结，VM/direct 共享同一双解析实现；
- `tool/example_precheck.sh` 的 debug 主链与 `tool/example_profile_smoke.sh` 的 profile 答复形态全绿，
  复用同一份指纹 AOT CLI；涉及 perf 数值的报告只采 profile，debug 只证明诊断覆盖；
- README、guide 与包 README 在开发期继续描述稳定 0.4.1；发布 MR 才更新版本锚点、聚合
  `changelog.d/0.5.0/`、冻结兼容语料并通过 `documentation-current`；
- 发布 MR 合回 `main` 后，同一 SHA 同步 GitHub、打 `patchbay-v0.5.0` 并按依赖顺序发布四包；实际发布
  完成后再运行 finalize、标记本文已发布并回收 `dev/0.5.0`。

## 回退边界

PB-050-01、PB-050-04、PB-050-08、PB-050-09、PB-050-10 可独立回退。PB-050-02 的 public source adapter 与内部 retention 实现应分 MR，
但 adapter 合入前必须已有完整 legacy 路径。PB-050-03 的失效信号是 cache 的前置底座，回退 cache 不得
回退全目录 fail-closed。PB-050-05 的队列与 PB-050-06 的 invocation context 各自独立；若取消确认无法在
VM/direct 两端形成同一事实，回退新增取消面，保留 direct timeout 后占用 slot 的现状，不以释放容量冒充完成。
