# Patchbay 0.5.0 版本计划

> 状态：规划中
>
> 范围真源：本文定义 0.5.0 的优先级、依赖和退出条件；[backlog](../backlog.md)
> 保存条目标题、动机、目标版本与实施状态。
>
> 发布方式：从稳定 `main` 创建 `dev/0.5.0`；范围、Proposal 与实现 MR 均以该分支为目标。
> 本文状态推进到 `RC` 即冻结范围，通过门禁后再由一个发布 MR 合回 `main`。

## 版本定位

0.5.0 的首要目标是**降低接入成本、降低入门门槛**：让人和 AI 都能从一个短入口开始，先完成安装、
连接与只读诊断，再按任务需要逐层展开 live catalog / describe、专项说明和完整 guide。消费者侧
`SKILL.md`、`INSTALL.md`、CLI 可发现性、瘦输出与大载荷 artifact 共同组成这条渐进式披露链，不能作为
发布末尾可有可无的文档附件。

host 可靠性、高频调用成本与 CLI 自动化契约治理仍是长期基石，但 0.5.0 不宣称在一个版本内“完成 CLI
基石”。本版只交付已经冻结边界、能够独立验证和回退的增量：收紧 provider、目录、审计和 invocation
四条边界，修复 REPL 流式终止答复，并降低 snapshot wait、带参数 invoke 与 semantics probe 的重复工作。
它不增加接入方业务命令；计划新增的 identifier action 是 protocol-owned UI 命令，不扩张 consumer
catalog namespace。

本版把三类工作明确分开：

1. 接入漏斗与渐进式披露先闭环，Skill 只保存任务路由和安全边界，命令事实继续由 descriptor、live
   catalog 与 help/describe 持有；
2. 已有契约无法兜住的正确性缺口继续作为发布阻断修复，特别是 snapshot source 的非 JSON、循环引用与
   活对象逃逸；
3. 会新增资源上限、缓存失效、异步投递或取消语义的工作先完成 Proposal 裁决，不以“性能优化”名义
   静默改变失败形态。

0.5.0 不以“所有路径都加缓存”为完成。每项优化必须先有基线，证明减少的是实际热点，并同时证明
valid payload 的稳定 JSON、整份 catalog fail-closed、semantics generation 和超时后容量保护没有漂移。

## 接入漏斗与渐进式披露契约

0.5.0 固定以下披露层级，后一层只在当前任务需要时读取，不允许把完整 guide 复制进 Skill：

1. **发现层**：Skill 的 name / description 只回答“何时使用 Patchbay”，不枚举完整命令面；
2. **起步层**：`SKILL.md` 只保存任务路由、安全边界、只读起步流程，以及去哪里取得下一层事实；
3. **实时契约层**：运行中的 `catalog`、`describe` 与 CLI help 持有命令、参数、gate 和 capability 事实；
4. **专项说明层**：安装、App 接入、权限、会话、capture 等细节按任务读取对应说明；
5. **完整参考层**：guide 与生成命令表负责穷举参考，大树和大 JSON 通过 brief / artifact 按需展开。

入口闭环固定为 `INSTALL -> SKILL -> identity/catalog/snapshot -> describe/help -> 专项说明/完整参考`。
同一命令事实不得在 Skill 与 guide 手写两份：Skill 中的命令示例由 registry 生成或经 CI 对拍；运行时
是否可用始终以 live catalog 为准。Skill 随仓库 tag 发布，不建立独立于四包的版本线；接入方使用的 App
依赖、CLI 和 Skill 必须来自同一兼容版本，兼容例外仍以兼容矩阵为准。

## 明确不进入 0.5.0

- 不把 snapshot canonical String 直接换成 digest：摘要仍需遍历全部字节，且当前 canonical 还承担
  精确去重；只有基准证明整体更优时才能作为 PB-050-02 的实现细节讨论。
- 不把 `revision.body` 直接替换成现有响应 body：canonical key 排序会改变有效 JSON 输出；PB-050-01
  必须用保持插入顺序的冻结副本单独解决活对象问题。
- 不把 source revision 作为 `PatchbaySnapshotSource` 的新参数或返回字段强塞进既有 typedef；旧接入方
  无修改继续工作是 PB-050-02 的验收条件。
- PB-050-04 只做量测；不用“透明降载”名义改变主动请帧或 `ui.wait` 时机。PB-050-07 接受后若使用索引，
  不用 identifier entry 快照替代 node 引用，也继续执行 tree revision、identity 与 generation 复核。
- 不在 direct timeout 时无条件释放 slot；缺少 cooperative cancellation 证明时继续保留现有容量保护。
- 不把 job ledger 纳入“无界事件”修复；现有每个 job 为 running 加一个终态，保留/淘汰契约不在本版改写。
- 不新增 `--jsonl`：REPL、`logs tail` 与 launcher 已承诺按行输出；PB-050-08 修的是终止错误逃到 one-shot
  pretty formatter 的契约破口。
- 不再新增 `ui capture` / `--out` 别名：CLI 已有 `capture root|target --output` 与 `blob get --output`，并负责
  分块、base64 解码、长度与 SHA-256 校验；PB-050-09 修复从 raw service 到这条安全路径的发现链，避免
  维持两套同义命令。
- 不在 PB-050-08 自动重连。REPL reconnect 复用 PB-040-30，须先裁决固定 session、App/device identity、
  runtime replacement 与重试预算，不能因“恢复体验”静默换 peer。
- PB-050-11 的日志 event wire/filter 不进入本版；它会改变公共 log source/query 契约，须独立 Proposal。
  接入方 log source 的即时归一化留在接入方仓，不等待核心契约。
- 不为 PB-050-13 新增 `legacy.dart` / `testing.dart` 暂存旧 surface，也不拆第五个 client package；两个
  公开 library 以 Proposal 的 2 + 8 封闭清单为准，真实 consumer 需求须在 DG-050-07 前进入清单。
- 不为压结构告警在 0.5.0 横切重写 CLI；只要求警戒线不再增长。范围内改动若触及已经确认应拆的巨型
  函数，须抽出至少一个可独立测试的阶段，或在 MR 中证明该函数没有继续承载新职责。
- 不把“CLI 基石已经完成”作为 0.5.0 的产品承诺。CLI 架构、公共面和可靠性会跨版本持续维护；本版只对
  范围表中已经冻结、可以验证和独立回退的增量负责，不能让无限延伸的内部治理挤占接入漏斗交付。
- PB-040-24、PB-040-28、PB-040-30 至 PB-040-37 继续留在 backlog，不借本次 host 治理扩张黑盒驱动、
  网络采集、回放或恢复产品面；允许 raw capture 的外部 observer 不能作为 DG-040-03 的解除证据。
  P1 能力批是仓主显式范围扩充，不适用本条。
- 不引入外部一体化 E2E 平台的常驻 Supervisor/worker、MCP、Console、case/suite DSL、原生/浏览器黑盒 driver、Element
  自动发现、代理控件归属或结构模糊 selector；PB-050-14 只解决现有 CLI 的目标亲和性。

## 能力批裁决记录（DG-050-08 至 DG-050-10，2026-08-25）

仓主授权代理裁决，授权与裁决过程记录于范围扩充 MR。

- **DG-050-08（合成 tap）**：进入 gesture 家族而非 semantics 家族；identifier 锚定 + 可选相对比例偏移，
  沿 DG-040-01 判例（比例坐标仅在锚定目标内合法，绝对屏幕坐标仍是非目标红线）。注入为真
  PointerEvent down/up，异常路径补 PointerCancel；准入复用 gesture 逐点校验与门后二次复核。不弃用
  `ui.semantics.tap`：辅助功能路径与指针路径语义不同，并存并在文档中给出选择指引，指针路径为
  防误击首选。双击与多点不进本条。
- **DG-050-09（遮挡准入）**：范围限定为点性用户 action（tap/longPress 类），派发前做 hit-test 遮挡
  复核，被非模态层覆盖即以稳定码拒绝。不提供 bypass 参数——确需穿透的场景属 domain command
  领域，不属于 UI 驱动面。非点性 action 遮挡语义不成立，维持现状。这是收紧方向的行为变更：
  错误码 additive，可达目标的既有行为以回归矩阵冻结；Proposal 接受前先落 repro 失败测试。
- **DG-050-10（reveal）**：定性为写操作，与写类命令同权过基础门 + 声明门，且**每步派发前重评门**、
  全程受单一 deadline 约束。实现留在 Semantics 域且**只派发 scroll action、逐容器显式授权**——不使用
  `SemanticsAction.showOnScreen`（其沿渲染父链冒泡，无法证明只影响已授权容器），不合成指针滚动，
  不引入 Element 全树打分启发式。预算由 reveal 专用 policy 三层承载（host 硬顶 → policy 上限 → 参数
  只能收紧）。懒加载补步判据为滚动步后 maxScrollExtent 增长；步数上限有硬顶，超限以稳定码如实拒绝。
  成功判据为目标露出且以固定采样口径报告 `reachability: pointer | semanticsOnly`（与 DG-050-09 三态
  对应），不伪造成功。
- **DG-050-11（domain 写命令过门，2026-08-25）**：`gates` 字段对 plane:domain 从 catalog-only 升为
  dispatch-enforced——sideEffect 非 none 的 domain 命令在 host 受理内评估声明门，拒绝复用既有
  rejection 形状；只读 domain 命令不加闸。这是收紧型行为变更，列为 P0 发布阻断（安全叙事缺口），
  实现前补 Proposal 冻结受影响面与兼容语义。
- 附带小裁决：PB-050-18 无启动身份字段的旧会话记录行为完全不变，仅诊断输出加 `identityUnverified`
  标注；PB-050-21 的 brief 视图为 opt-in，本版不翻转默认输出。
