# Patchbay 0.6.0 版本计划

> 状态：规划中
>
> 版本分支：`dev/0.6.0`，从稳定 `main` 的 `788214c4` 创建；范围、Proposal 与实现 MR 均以该分支为目标。
>
> 范围真源：本文定义 0.6.0 的优先级、依赖、验收与退出条件；[backlog](../backlog.md) 保存条目标题、

## 版本定位

0.6.0 是 **1.0 前的表面收敛与治理减债版本**。0.5.0 已经形成安全优先的 Flutter 自动化内核，但默认
公共 API、CLI 任务入口、输出投影与 gate 执行边界仍要求使用者先理解内部结构。本版不以增加能力为目标，
而是把已经存在的能力整理成可以长期承诺的产品表面：

1. 同一任务只有一个推荐入口，身份域和执行通道不再成为使用前置知识；
2. 普通 consumer、host implementer 与 protocol implementer 使用不同的公共 Dart 入口；
3. 同一个输出事实只有一个 descriptor/schema 投影真源；
4. 同一个安全声明只有一个可追溯执行边界；
5. invocation、bridge、仓库工具与版本治理的内部复杂度在 1.0 前完成减债。

本版允许经过 Proposal 裁决的 source breaking 与稳定 JSON 演进，但每一项必须在实现前冻结迁移窗口、
老 reader/host 降级和独立回退边界。除安全阻断缺陷外，0.6.0 的新增命令能力预算为零。

## 范围分级

### P0：发布阻断

| 编号 | 关键验收 |
|---|---|
| PB-060-01 | CLI 建立 canonical `ui perform` 与 `target:/semantics:/node:` selector；仅 tap 强制显式选择 semantics 或 pointer，不自动回退；旧写入口 0.6.0 保留告警、1.0 删除，help/Skill/迁移表同步 |
| PB-060-02 | core 公共 Dart API 按角色分层并取自足闭包，三个 core 入口冻结为 98 consumer、136 host、141 protocol；Flutter 默认面只比 consumer 多四个 widget 自有符号（102），新增 195 符号的显式 host 入口；API checker 按入口冻结清单，并提供 0.5.x source 迁移表 |
| PB-050-40 | brief 删除规则、单一 artifact 与完整机器输出由 descriptor/schema 声明；同一份 0.5.x descriptor-less 输入的 brief golden 逐字节不变，老 host 缺声明时有冻结降级，不再按命令扩 CLI 手工投影表 |
| PB-050-39 | core host 统一负责 descriptor、sideEffect、声明门与审计执行真源；Flutter bridge 只保留 UI 特有准入；每类 gate 都能回答声明者、评估点、拒绝形状与老 consumer 降级 |
| PB-060-04 | 版本启动顺序、active version 切换、已发布版本残留 target、草案瞬时事实与范围双向对账进入机器门禁；本版计划与 backlog 不再依赖人工发现时间语义漂移 |

### P1：本版目标

| 编号 | 关键验收 |
|---|---|
| PB-050-34 | 冻结 direct-target 与 user-like action 的遮挡语义：注册文本目标是显式自动化面，不伪装成用户触达；descriptor/help 明示该差异，不引入隐式策略切换 |
| PB-050-35 | `ui.reveal` 区分已挂载但被遮挡、identifier 不存在与无可授权滚动容器；新增拒绝形状进入错误码 ratchet、迁移表与 VM/direct 兼容矩阵 |
| PB-050-36 | 以仓内 widget 三方对照冻结预算门顺序：调用级硬顶前置求值，容器级 policy 只约束实际驱动容器；运行时保持现状，descriptor/help 与契约测试明确两层预算 |

| PB-050-38 | 按状态机阶段拆 semantics bridge、Flutter service host、reveal engine、host invoker 与 snapshot payload 五个已登记热点；每阶段可独立失败注入、独立测试和独立回退，不把 CLI 侧对象混入本条，也不按文件行数横切重写 |
| PB-060-03 | 建根 pub workspace 与私有 repo-tooling 边界；GitLab/GitHub CI 调同一组仓内任务；四包候选依赖、codegen、release 与检查命令不再靠多份手写循环同步 |
| PB-060-06 | transport/protocol 解码边界建立确定性畸形载荷 harness，覆盖随机截断、字段类型替换与有界超长字符串；所有公开 decoder 都必须类型化拒绝、不部分接收、不挂死，并能用固定 seed 复现 |
| PB-060-07 | GitLab/GitHub 复用同一仓内任务生成逐包 LCOV 与可下载报告，先作为 informational lane 建立 1.0 前覆盖地图；本版不设百分比硬门、不因生成代码或不可达平台分支制造假精度 |
| PB-060-05 | 交付英文 10 分钟最短路径与可量测接入漏斗；无先验用户/Agent 完成 install→identity→catalog→snapshot→安全写操作→capture，并记录用时、失败点与读取层级 |
| PB-050-29 | `doctor` 的隔离文件定位信息不再原样泄露本机绝对路径，同时保留操作者可定位性并与 trace/workspace 脱敏原则一致 |

## 明确不进入 0.6.0

- 不新增日志、网络采集、回放、自动恢复、平台权限或黑盒驱动能力；PB-050-11、PB-040-24、PB-040-28、
  PB-040-30 至 PB-040-37 继续不进入本版范围。
- 不做自动重连、自动换 session、自动跨身份域回退；恢复与回退都不得静默替换调用方以为正在操作的 peer
  或执行通道。
- 不把 `ui.reveal` 扩成通用导航，不引入模糊 selector、Element 自动发现、全树打分或绝对屏幕坐标。
- 不因结构告警横切重写所有长文件；只拆已确认存在多阶段职责的热点，行为变化必须另立条目与 Proposal。
- 不把 snapshot single-flight 主动放弃阈值（PB-050-30）夹进治理版本；没有真实挂死证据前继续沿用已裁决
  语义，需要推进时先修订资源 Proposal。
- 不为会话记录目录版本化建立预防性条目：PB-050-19 与 PB-050-31 已随 0.5.0 交付，
  [架构设计](../design.md)已经裁决记录 `schemaVersion` 保持 `1`、新字段松读追加；PB-050-29 只是可独立
  回退的 doctor 输出脱敏，不再与前两项合批。将来出现必须破坏结构的真实需求时，按既有结论改用新目录名，
  并另立 PB 与 Proposal 裁决迁移，而不是在本版保留一个没有验收边界的候选。
- 不提前发布 1.0 的长期兼容承诺；0.6.0 只产出一份“是否已可承诺”的候选评估。

## 依赖与实施顺序

1. **M0：版本启动与基线。** `dev/0.6.0` 已从稳定 `main` 创建；本范围 MR 将计划推进到“规划中”，把
   backlog target 与 `check_planning` active version 原子切到 0.6.0，并冻结 0.5.0 的 API、稳定 JSON、
   error code、结构警戒线与兼容语料作为 breaking diff 输入。
2. **M1：Proposal 裁决。** PB-050-36 先在可重复的仓内 widget harness 取得决定性复现，DG-060-04/05 再冻结安全语义与
   PB-050-26/36 的处置；DG-060-01 据此冻结任务入口，DG-060-03 根据 canonical 入口冻结输出投影，
   DG-060-02 可独立裁决。未接受的 Proposal 只允许原型和失败测试。
3. **M2：治理底座。** PB-060-04、PB-060-03、PB-050-37、PB-050-38 按独立 MR 推进；结构拆分与状态模型
   均要求零外部语义变化，否则停止并另走裁决。
4. **M3：安全边界。** 实现 PB-050-39、PB-050-34、PB-050-35 以及 Proposal 接受的 PB-050-26/36 方向；
   VM/direct 共享同一拒绝语义，旧 reader 对 additive 字段与错误码按 Proposal 降级。
5. **M4：产品表面。** 实现 PB-060-01 与 PB-060-02；旧 CLI/API 迁移窗口与新入口同时交付，禁止只加新
   façade 而永久保留第二套推荐面。
6. **M5：输出与接入。** 实现 PB-050-40、PB-060-05、PB-050-33，并把 help、Skill、INSTALL、README
   Quick Start / “Choose a day-to-day workflow”、英文最短路径、候选依赖和发布说明对齐到最终表面。
7. **M6：独立小件。** PB-050-29、PB-050-32、PB-060-06 与 PB-060-07 各走独立 MR；PB-060-06 必须在
   PB-050-40 实现前合入并先覆盖新增 projection wire 的畸形矩阵，其他三项可在不触碰热点和 Proposal 的前提下随时插队。
8. **RC。** 冻结范围，只接发布阻断修复；固定候选 SHA 后运行全部门禁、debug/profile example 预检、
   Android 真机、iOS 模拟器与 consumer 验收，并保持至少 72 小时无 P0/P1 重开。代码变化生成新候选并重计。

## MR 与分支治理

- 后续版本一律先从最新稳定 `main` 创建并推送空的 `dev/<SemVer>`，再从版本分支创建范围、Proposal 与实现
  分支；所有在版 MR 以该版本分支为目标，只有发布 MR 把定版版本分支合回 `main`。
- 本版五份 Proposal 各走独立 MR；PB-060-01/02、PB-050-39/40/26 与 PB-050-34/35/36 不在同一个实现
  MR 混合裁决。共同底座先合入，堆叠不超过三层。
- 每个实现 MR 只修改自己的 backlog/changelog 碎片，声明独立验收、迁移和回退边界；集成候选只固定来源
  SHA 做联合验收，不在候选分支修语义冲突。
- MR 描述使用中文，并写明目标分支、依赖链、Proposal/design gate、实际检查、真机状态与剩余风险。

## 验证与退出条件

- 四包与 example 的 format、analyze `--fatal-infos`、test、wire/command/protocol CLI/command docs codegen
  零漂移、API surface、结构硬规则、planning 与 `repo_tasks.dart release --version 0.6.0 --check` 全绿；GitLab/GitHub
  调用同一仓内任务定义，不再靠复制命令保持一致。
- 已验证下限 Flutter 3.44.0 / Dart 3.12.0 与当期 CI SDK 同时为阻断 lane；提高下限必须另走 Proposal。
- 任务入口验收由无先验操作者完成：只读发现、文本输入、语义点按、真实指针点按、reveal 与 capture 都能
  从任务描述找到唯一推荐入口；失败时能从稳定拒绝判断目标不存在、被遮挡、策略拒绝或传输失败。
- 默认 consumer API、host API 与 protocol/wire API 各有逐 library 封闭 golden；默认 Flutter 入口只暴露
  core consumer 与 `PatchbayKey`、`PatchbayRoot`、`PatchbayRootController`、`PatchbayUiRegistry`，不再
  re-export raw wire/host 全表；任何新增符号必须先说明属于哪类使用者。
- descriptor 投影覆盖所有可能产生大载荷或 brief 输出的协议命令；新增命令不再同时修改 brief 表、artifact
  disposition、help 与 golden 四份事实；相同 0.5.x descriptor-less 输入的 brief 输出逐字节不变，新 host
  的 additive catalog 字段不伪装成跨版本字节不变。
- gate 矩阵覆盖 base、descriptor、semantics policy、gesture policy 与 reveal 每步重评；声明与执行不可漂移，
  审计能够如实区分 notDeclared、passed、rejected 与未执行。
- PB-050-36 的决定性 widget 三方对照在裁决前可稳定复现；预算门顺序无论保持还是改变，都有 Proposal、
  help 与 VM/direct 用例共同证明，不让“已露出成功”和“参数越界拒绝”的优先级继续靠源码阅读推断。
- transport 畸形载荷 harness 以固定 seed 覆盖每个公开 decoder 的截断、类型替换与有界超长字符串，失败
  必须类型化、不得部分接收、挂死或泄露原始载荷；新增 wire 字段先进入该 harness 再实现业务投影。
- coverage lane 在 GitLab/GitHub 由同一仓内任务生成逐包 LCOV 与可下载报告，本版只提供趋势和未覆盖分支
  地图，不用单一百分比作为硬门；是否建立分包下限留给有稳定基线后的独立裁决。
- invocation 属性测试和既有失败注入共同证明终态、slot、取消、replay、deadline 与 dispose 不变式；拆分前后
  稳定 JSON、错误码、审计与 VM/direct 语料逐字节对账。
- 规划门禁拒绝已发布版本上的非终态 target、未激活版本的范围漂移、版本计划中的瞬时分支事实，以及未按
  `main → dev/<SemVer> → 范围/Proposal MR` 顺序启动的新版本。
- 英文最短路径与中文完整 guide 分层；记录至少一次无先验用户和一次无先验 Agent 的 time-to-first-snapshot、
  time-to-first-safe-write、失败点与实际读取层级，不能用直接喂完整 guide 替代渐进式披露验收。
- 先在仓内 example 跑 `tool/example_precheck.sh` 与 `tool/example_profile_smoke.sh`，再交 consumer 真机验收；
  设备证据与两条 example 预检必须对应同一候选 SHA。
- [`docs/verification/README.md`](../verification/README.md) 对每份证据标明版本锚点、证明范围与未证明范围；
  RC 新增证据必须入索引，阻塞报告、仓内预检和 consumer 真机事实不得互相冒充。
- 发布说明首段给出 CLI、Dart API、JSON 与错误码迁移表；每条旧入口/字段都有本版即删、保留一版并告警或
  保留至 1.0 的明确结论，不留“以后再说”。
- RC 形成 1.0 候选评估：每个公共入口、稳定 JSON 字段、错误码和资源上限都能回答 1.0 后是否继续承诺；
  未能回答的项目必须在发布前修正或明确阻断 1.0，而不是把新功能塞回 0.6.0。

## 发布与回退

- P0 五个交付单元各自独立回退；入口回退不删除旧路径，API 回退不连带恢复 CLI 内部 surface，投影回退保留
  0.5.0 brief golden，gate 回退不得撤销 0.5.0 已交付的 domain 写命令强制门。
- 结构拆分按单函数/阶段 MR 回退；decoder harness、coverage lane、会话诊断脱敏、lint、候选依赖与英文文档
  各自独立回退。
- 候选通过后由发布 MR 将 `dev/0.6.0` 合回 `main`，同步 GitHub、打 `patchbay-v0.6.0` 并按依赖顺序发布
  四包；实际发布完成后再运行 finalize、标记本计划已发布并回收版本分支。
