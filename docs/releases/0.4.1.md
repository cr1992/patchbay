# Patchbay 0.4.1 版本计划

> 状态：规划中
>
> 范围真源：本文定义 0.4.1 的优先级、依赖和退出条件；[backlog](../backlog.md)
> 保存条目标题、动机、目标版本与实施状态。
>
> 发布方式：从稳定 `main` 创建 `release/0.4.1`；实现 MR 以该分支为目标，通过
> RC 门禁后再由一个发布 MR 合回 `main`。

## 版本定位

0.4.1 是 0.4 系列的质量补丁，不扩展公共 API、wire、命令 descriptor、稳定 JSON、
状态机或安全边界。本版只做三件事：

1. 让四包的 pub.dev 评分在真实发布 archive 上可复现、可阻断、可回查；
2. 拆解 `patchbay_cli` 的高冲突文件与执行流，同时收敛跨平台系统命令；
3. 建立发布 finalize 机制，使已发布范围、延期范围和未结验收证据不再混在一张表里。

## 范围分级

### P0：发布阻断

| 编号 | 关键验收 |
|---|---|
| PB-041-01 | 对四个实际发布 archive 使用 pub.dev 当期 Pana 跑出零扣分；同版内部依赖用临时本地解析消除假扣分；发布后 score API 的 `grantedPoints == maxPoints` 并留存脱敏结果 |
| PB-041-02 | finalize 先生成“已发布 / 已延期 / 仅缺证据”计划，再由 maintainer 显式 apply；不能批量删除“实现中”或把未结真机验收冒充完成 |
| PB-040-39 | 进程存活、文件权限与平台命令统一走可注入抽象；Windows/macOS/Linux 的退出码、不可用形态与安全拒绝有对应测试 |

### P1：本版目标

| 编号 | 关键验收 |
|---|---|
| PB-040-38 | Manifest walkthrough、snapshot diff 与 job wait 从 `cli.dart` 提取为独立 Runner；已有命令帮助、JSON、stderr、退出码与超时语义的 golden 不变 |
| PB-040-40 | 在 Runner 边界稳定后完成 `commands/`、`platform/`、`session/`、`manifest/` 分层；公共 export、bin 入口、descriptor 与兼容语料零漂移 |

### P2：本版不排期

不用低优先级新功能填充补丁版；P0/P1 完成后直接进入 RC。

## 明确不进入 0.4.1

- PB-040-24 轨迹回放、PB-040-30 引导式会话恢复、PB-040-31 长流程进度面和
  PB-040-32 字段级敏感输入都会新增或改变公共契约，继续留在 backlog 并先过 Proposal。
- PB-040-28 继续受上游采集前脱敏能力阻塞，不以“先收集再脱敏”降级安全边界。
- PB-040-33 至 PB-040-37 涉及系统弹窗、真机权限事实源和 App 重启/重附加，按平台专项版本另行规划。
- `text.set` formatter 与 `text.enter` submit 回调属于公共行为变更，未经 Proposal 不改写
  0.4.0 已发布契约。

## 依赖与实施顺序

1. **M0：版本与发布治理**——开建 `release/0.4.1`，切换 CHANGELOG 队列与兼容语料目标；
2. **M1：评分、finalize 与平台底座**——PB-041-01、PB-041-02 与 PB-040-39 拆成三个独立 MR；
3. **M2：执行流提取**——PB-040-38 在平台底座合入后开始，先冻结行为 golden 再移动实现；
4. **M3：目录分层**——PB-040-40 仅在 PB-040-38 合入后开始，不让两个 MR 并行移动同一文件；
5. **RC**——冻结范围，只接发布阻断修复，跑完兼容、双模式 example 与 pub 门禁。

## 验证与退出条件

- 四包 format、analyze `--fatal-infos`、test、codegen/check 与 `release_prep --version 0.4.1 --check`
  全绿；
- 0.4.0 host ↔ 0.4.1 CLI、0.4.1 host ↔ 0.4.0 CLI 的兼容语料全绿，公共 catalog、
  response schema、错误码与退出码无未裁决变化；
- `tool/example_precheck.sh` 的 debug 主链全绿，`tool/example_profile_smoke.sh` 的 profile
  答复形态全绿；两者都复用同一份指纹 AOT CLI；
- 四个实际发布 archive 在 pub.dev 当期 Pana 下无扣分，发布后 score API 确认
  `grantedPoints == maxPoints`；
- README、guide、包 README、架构 SVG 与发布阶段一致：开发期不提前宣称 0.4.1 已发布，
  发布候选只描述已经验收的 0.4.1 能力；打 tag 前通过 `documentation-current`；
- 发布 MR 合回 `main` 后，同一 SHA 同步 GitHub、打 `patchbay-v0.4.1` 并按依赖顺序
  发布四包；随后运行 finalize、将本文标为已发布并回收 `release/0.4.1`。

## 回退边界

本版不引入数据迁移或新协议。任一实现 MR 都必须能独立回退；若重构后出现行为漂移，
直接回退该 MR，不在 RC 中为保留新目录结构而改写旧契约。
