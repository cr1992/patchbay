# PB-060-05 接入漏斗记录模板

> 状态：Agent 已量测三次（第三次在脚本修复后达成 10 分钟目标）；用户待量测
>
> 版本锚点：0.6.0

## 用途

本文件是记录模板，不是已完成的验收报告。它的字段由 PB-060-05 的验收条件固定：至少一次无先验
用户、一次无先验 Agent，各自走一遍 [`docs/quickstart.md`](../quickstart.md) 的六步（install →
`identity` → `catalog` → `snapshot` → 安全写操作 → `capture`），并如实记录用时、失败点与实际读取
层级。量测执行本身不在撰写本模板的 MR 范围内，由后续任务派无先验受试者按下表逐列填写。

**受试者选取要求**：受试者在开始前不得读过 `docs/quickstart.md`、`docs/guide.md`、
`skills/use-patchbay/` 或本仓库任何 Patchbay 专属文档；"无先验" 指对 Patchbay 本身没有先验，不
要求对 Dart/Flutter 没有先验（[`docs/quickstart.md`](../quickstart.md) 的前置条件本身就假定
读者已有可用的 Dart/Flutter 工具链）。同一份记录不得用直接投喂完整 guide 替代渐进式披露——受试者
只应拿到 [`docs/quickstart.md`](../quickstart.md) 这一个入口，读到更深层文档必须是他们自己顺着
本页末尾的链接走下去的结果，而不是被预先告知。

## 填写字段

| 字段 | 含义 |
|---|---|
| 受试者类型 | `无先验用户` 或 `无先验 Agent` |
| 候选 SHA | 受试者开始量测时的仓库提交，六步全部针对同一个 SHA |
| 设备/模拟器 | 受试者 `flutter run` 的实际目标（如「iOS 模拟器」「Android 真机」「macOS 桌面」），不记录设备序列号或型号等可识别信息 |
| time-to-first-snapshot | 从受试者拿到 `docs/quickstart.md` 链接开始计时，到第 3 步 `catalog` 成功和第 4 步 `snapshot` 成功中较晚的那个时刻——即真正跑出一份 snapshot 为止 |
| time-to-first-safe-write | 到第 5 步 `ui perform` 第一次成功受理为止 |
| time-to-capture | 到第 6 步 `capture` 成功产出文件为止（即走完全部六步的总用时） |
| 失败点 | 每一次卡壳记一行：`步骤` + 观察到的 `error.code`（或「无 error 信封」时的现象）+ 受试者自己的处置动作；没有失败就写「无」 |
| 实际读取层级 | 受试者除 `docs/quickstart.md` 外还读了什么：`仅最短路径` / `guide.md` 的具体章节锚点 / `skills/use-patchbay/` 的具体文件；如实记录，不因为"本该只读最短路径"就少记 |
| 结论 | 六步是否在 10 分钟内独立走通；若没有，卡在哪一步、是文档问题还是环境问题 |

## 第三次量测的方法学说明

- **候选 SHA**：`1279c581`。与前两行不是同一个 SHA——前两行量的是 quickstart 修复前后，本行量的是
  `example_session.sh` zsh 自定位修复合入之后的当前形态。三行之间只可比趋势，不可当同一候选的重复观测。
- **受试者检出移除了 `CLAUDE.md` 与 `AGENTS.md`**：Agent 宿主会把仓内这两份文件自动注入系统提示，
  而 `AGENTS.md` 写着联调姿势（AOT 复用、`example_session.sh` 的存在与用法）——那正是本量测要检验
  受试者能否**从 quickstart 自己发现**的东西。不移除就等于预先投喂。前两行未作此处理，这是三行之间
  的一处方法学差异，如实记录。
- **环境限制一处**：受试者按文档收尾执行 `git checkout -- .../pubspec.lock` 时被其所在 harness 的
  权限分类器拒绝，与 patchbay 无关；`example_session_stop` 正常退出 0。
- **受试者报告的三处文档粗糙处**（均未导致失败或返工）：第 2 步 `identity` 的「You'll see」列的是
  `--json` 才有的完整握手字段，而该步给的命令不带 `--json`；非交互 helper 的状态行是中文，而
  quickstart 本身是英文页；文档说 helper 会 `export PATCHBAY_SESSION_ID` / `PATCHBAY_SESSION_DIR`，
  但没说每条命令都起新 shell 的执行器（多数 Agent 宿主如此）要如何接住这两个值。三处已随本 MR 修入
  `docs/quickstart.md`。

## 边界

- **无先验用户一行仍是空的**，因此 PB-060-05 的验收条件（至少一次无先验用户 + 一次无先验 Agent）
  尚未满足；在那一行填入真实量测前，不得引用本文件宣称漏斗量测条件已完成。Agent 一侧已达成
  10 分钟目标这件事只能按 Agent 说，不能外推到人。
- 三行 Agent 记录分别对应三个不同的候选 SHA（`267547f0` / `028e3048` / `1279c581`），因为每一次
  量测都直接导致了一次文档或脚本修复。它们之间只可比趋势（997s → 651s → 198s），不可当同一候选的
  重复观测；单次量测也只是一个样本，不构成分布。
- 模板本身不替代 [`0.5.0-onboarding-skill-acceptance.md`](0.5.0-onboarding-skill-acceptance.md)
  已经证明的只读闭环；本模板覆盖的是 0.6.0 表面下、含安全写操作与 capture 的完整六步，且明确要求
  无先验受试者而非 maintainer 侧近似。
