## profile smoke 结果与失败归因

`tool/example_profile_smoke.sh <ios-simulator-udid>` 输出：

```
[session] 预构建 profile .app（Simulator，不需要签名）（首次最慢）
[session] 预构建失败（profile .app（Simulator，不需要签名））
冒烟未开始：会话启动失败（原因见上方 [session] 行）
```

`example_session.sh` 把构建器的 stdout/stderr 丢弃，为定位根因，在 example 目录下直接复现了同一条
构建命令：

```
$ flutter build ios --profile --simulator --no-pub
Profile mode is not supported for simulators.
```

进一步定位到 Flutter SDK 自身的硬编码检查（`flutter_tools/lib/src/commands/build_ios.dart`）：
`environmentType == EnvironmentType.simulator && !buildInfo.supportsSimulator` 时无条件
`throwToolExit`；iOS 平台只有 debug 的 `BuildInfo.supportsSimulator` 为真，profile / release 恒为假。

**归因：环境/工具链限制，非候选缺陷。** Flutter 对 iOS 平台的 profile（以及 release）构建本身就不支持
以 Simulator 为目标，与 patchbay 候选的实现或 `dev/0.6.0` 上的任何改动无关；这一限制在任意 SHA、任意
Flutter 3.44.x 稳定版上复现结果都相同。该结论也与 `tool/example_profile_smoke.sh` 脚本头部注释里
「该缺陷……最终由接入方在 iOS 真机上撞出来（iOS 联调只能用 profile）」的措辞一致——脚本作者原本设想
的 iOS profile 目标就是真机，不是模拟器。

据此，本次派发固定的环境（iPhone 17 Pro 模拟器）在原理上无法承载 iOS 侧的 profile smoke 一段；
未再重复重试。iOS 侧的 profile smoke 覆盖需要一台真实 iOS 设备，或改用 Android 目标重跑同一脚本
（Android 平台无此限制）。

### profile smoke 结果

`tool/example_profile_smoke.sh <android-serial>` 全部通过，脚本末行：`通过 17，观察 0，失败 0`。

| 分组 | 步数 | 结果 |
|---|---:|---|
| 非 debug 下必须可用的面（capture root / identity / catalog / snapshot / semantics tree / 两种 tap） | 7 | 全绿 |
| reveal 答复形态（PB-050-17，不依赖任何 debug-only API） | 3 | 全绿 |
| debug-only 的面（只验类型化降级，不写死期望） | 4 | 全绿，形态见下 |
| 输出漏斗在非 debug 下的形态（PB-050-20 / PB-050-21） | 3 | 全绿 |

debug-only 一组的实测形态：

- `ui inspect on`：退出 `5`，`code=inspectorUnavailable`——类型化拒绝，不是退出 3。
- `ui widget-tree`：退出 `0`，实测返回**非空** `data`（漏斗形态 `spill=nonempty-spilled
  brief=nonempty-omitted`：数据超阈值落盘，brief 视图省略正文）。
- `ui render-tree` / `ui focus-tree`：退出 `0`，`data` 为空（`spill=empty-inline
  brief=empty-kept`：空但未落盘，brief 视图保留空值）。

这与脚本头部注释记录的历史观察（三棵树在 profile 下全部退 0 配空 `data`）不完全相同：本次 Android
真机上 `widget-tree` 实际带回了非空数据，`render-tree` 与 `focus-tree` 仍为空。脚本按设计不对这类
形态判红（其"不判失败但要看见"的设计意图见脚本头部注释），本报告如实记录这一实测差异，不代表这是
缺陷，也不代表已裁决三棵树在非 debug 下应统一表现为空或非空——是否改为拒绝、补 capability 声明还是
保留现状，仍属待定的设计裁决。

`capture root` 在本次 Android profile 会话中退出 `0`（截图产物落盘 25972 字节），未复现脚本注释
提到的历史缺陷（`capture` 在 profile 必然退 3，BUG-20260819-02）——该缺陷在 Android 真机、当前
候选 SHA 上未复现。
