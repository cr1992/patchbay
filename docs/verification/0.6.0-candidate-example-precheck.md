## profile smoke 结果与失败归因

`tool/example_profile_smoke.sh <ios-simulator-udid>` 输出：

```
[session] 预构建 profile .app（Simulator，不需要签名）（首次最慢）
[session] 预构建失败（profile .app（Simulator，不需要签名））
冒烟未开始：会话启动失败（原因见上方 [session] 行）
```

`example_session.sh` 把构建器的 stdout/stderr 丢弃，为定位根因，在 example 目录下直接复现了同一条
构建命令：

```
$ flutter build ios --profile --simulator --no-pub
Profile mode is not supported for simulators.
```

进一步定位到 Flutter SDK 自身的硬编码检查（`flutter_tools/lib/src/commands/build_ios.dart`）：
`environmentType == EnvironmentType.simulator && !buildInfo.supportsSimulator` 时无条件
`throwToolExit`；iOS 平台只有 debug 的 `BuildInfo.supportsSimulator` 为真，profile / release 恒为假。

**归因：环境/工具链限制，非候选缺陷。** Flutter 对 iOS 平台的 profile（以及 release）构建本身就不支持
以 Simulator 为目标，与 patchbay 候选的实现或 `dev/0.6.0` 上的任何改动无关；这一限制在任意 SHA、任意
Flutter 3.44.x 稳定版上复现结果都相同。该结论也与 `tool/example_profile_smoke.sh` 脚本头部注释里
「该缺陷……最终由接入方在 iOS 真机上撞出来（iOS 联调只能用 profile）」的措辞一致——脚本作者原本设想
的 iOS profile 目标就是真机，不是模拟器。

据此，本次派发固定的环境（iPhone 17 Pro 模拟器）在原理上无法承载 iOS 侧的 profile smoke 一段；
未再重复重试。iOS 侧的 profile smoke 覆盖需要一台真实 iOS 设备，或改用 Android 目标重跑同一脚本
（Android 平台无此限制）。
